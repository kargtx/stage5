# КИС «Автосервис: Программная модификация ЭБУ (Чип-тюнинг)» — 2026 г.

Корпоративное программное веб-приложение, реализующее спроектированный **Детальный бизнес-сценарий (ДБС)** оказания услуг чип-тюнинга двигателей в соответствии со стандартами СТП УГАТУ.

### 2. Соответствие схеме бизнес-процесса (BPMN 2.0)
Приложение строго реализует все 5 ролевых дорожек и 2 индивидуальных подпроцесса:

1. **Подпроцесс 1: Оформление заявки клиента и выпуск наряд-заказа (Гайнанов Д.И.)**:
   - `Сеанс 1.3`: Регистрация контрагентов в справочнике `Client` и автомобилей в `Car` с декодированием VIN и определением модели контроллера ЭБУ (Bosch MG1 / Continental SIMOS / Bosch MED17).
   - `Сеанс 1.5`: Оформление электронной заявки `Service_Request`, подбор конфигурации (Stage 1 / Stage 2 / Euro-2), расчет расчетного прироста мощности и крутящего момента.
   - `Сеанс 1.8`: Утверждение юридического договора подряда `Work_Order` (Наряд-заказ), назначение мастеров, фиксация подписи клиента, генерация официального бланка для печати.
2. **Входной контроль качества (Quality Gate)**:
   - `Сеанс 1.10`: Аппаратная диагностика ДВС `Diagnostics_Card`. При обнаружении критических кодов неисправностей DTC чип-тюнинг блокируется, автомобиль перенаправляется на механический ремонт. При норме параметров — допуск в цех калибровки.
3. **Подпроцесс 2: Исполнение заказа, калибровка с комментарием мастера и выдача акта (Гарифуллин К.Р.)**:
   - `Сеанс 1.13`: АРМ Калибровщика. Вычитывание заводского дампа ROM (хэш SHA-256), проверка контрольной суммы Checksum, прошивка ЭБУ с анимированным индикатором прогресса, аварийный режим `Recovery Mode`, и **обязательный развернутый «Технический комментарий мастера»** (система программно валидирует и запрещает сдачу работы без комментария!).
   - `Сеанс 1.16`: Оформление `Work_Completion_Act`, фискальный кассовый расчет по 54-ФЗ, генерация официального гарантийного сертификата на 24 месяца, закрытие наряда.

### 3. Реляционная база данных в 3NF (SQLite)
В базе данных `service_station.db` реализована концептуальная и логическая модель из 8 нормализованных таблиц (3-я нормальная форма, 3NF):

1. **`Client`** — `(id_client, client_fio, phone_number, email)`
2. **`Car`** — `(vin_code, brand_model, engine_model, ecu_type, plate_number, id_client)`
3. **`Tuning_Package`** — `(id_package, name, stage, power_gain_hp, torque_gain_nm, base_price, description)`
4. **`Service_Request`** — `(id_request, vin_code, id_package, request_date, preliminary_cost, eco_options, status)`
5. **`Work_Order`** — `(id_order, id_request, order_date, assigned_master, assigned_tuner, total_cost, order_status, client_signature)` *(3NF: vin_code исключен, связь строго через id_request)*
6. **`Diagnostics_Card`** — `(id_card, id_order, check_date, dtc_errors_found, dtc_codes, boost_pressure_bar, fuel_correction_ltft, diagnostic_verdict)`
7. **`Order_Execution`** — `(id_execution, id_order, stock_file_hash, mod_file_hash, checksum_valid, flashing_tool, execution_date, technical_comment)` *(обязательный комментарий мастера)*
8. **`Work_Completion_Act`** — `(id_act, id_order, act_date, warranty_period_months, payment_type, fiscal_receipt_number, client_signature_confirmed)`

### 4. Как запустить приложение

#### Вариант 1 (Рекомендуемый):
1. Запустите двойным кликом файл `start.bat`.
2. Автоматически запустится локальный HTTP-сервер на базе стандартной библиотеки Python (без необходимости установки дополнительных pip-библиотек) и в браузере откроется адрес:
   ```
   http://localhost:8000
   ```
