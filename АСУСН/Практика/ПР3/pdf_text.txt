Практическое занятие № 3 
Тема: Разработка алгоритма работы системы в нештатной ситуации (потеря связи, 
отказ датчика) 
Цель занятия: освоить методику разработки алгоритмов поведения АС СН в нештатных 
ситуациях; научиться применять методы диагностики отказов и обеспечивать безопасный 
переход в резервный режим. 
Продолжительность: 2 часа. 
 
Формируемые компетенции:  способность разрабатывать алгоритмическое и 
программное обеспечение для критически важных систем. 
 
Теоретическая часть 
 
Нештатные ситуации в АС СН: 
1. Потеря связи  между компонентами системы (датчик –контроллер, контроллер –
SCADA, контроллер–контроллер). 
2. Отказ датчика (обрыв, короткое замыкание, выход за диапазон, «залипание»). 
3. Отказ исполнительного механизма  (неоткрытие/незакрытие клапана, отказ 
насоса). 
4. Потеря электропитания. 
5. Перегрузка вычислительного ресурса. 
Методы диагностики отказов датчиков: 
 проверка диапазона (значение вне допустимых пределов); 
 проверка скорости изменения (слишком быстрое или медленное); 
 сравнение с резервным датчиком (мажоритарная обработка); 
 проверка «залипания» (значение не меняется длительное время); 
 проверка достоверности (например, физическая невозможность значения). 
Принципы обработки нештатных ситуаций: 
1. Обнаружение — фиксация отклонения от нормального режима. 
2. Идентификация — определение типа и причины нештатной ситуации. 
3. Изоляция — отключение неисправного элемента. 
4. Реконфигурация — переход на резервный режим. 
5. Оповещение — передача информации оператору. 
6. Протоколирование — запись событий в архив. 
 
 
Задание 
Разработать алгоритм работы системы в одной из нештатных ситуаций (по 
варианту). 
 
Вариант 1. Потеря связи между контроллером и SCADA-системой. 
Требуется: 
1. Описать признаки потери связи. 
2. Разработать алгоритм обнаружения потери связи (тайм -аут, счётчик пропущенных 
пакетов). 
3. Разработать алгоритм действий контроллера при потере связи: 
 переход в автономный режим; 
 поддержание технологического режима; 

=== PAGE 2 ===
 буферизация данных; 
 попытки восстановления связи. 
4. Разработать алгоритм действий SCADA при потере связи: 
 индикация аварии; 
 переключение на резервный канал; 
 оповещение оператора. 
5. Построить блок-схему алгоритма. 
6. Описать критерии восстановления связи. 
 
Вариант 2. Отказ датчика давления (обрыв или короткое замыкание). 
Требуется: 
1. Описать признаки отказа датчика. 
2. Разработать алгоритм обнаружения отказа: 
 проверка диапазона (4–20 мА); 
 проверка скорости изменения; 
 сравнение с резервным датчиком. 
3. Разработать алгоритм действий при отказе: 
 переход на резервный датчик; 
 при отсутствии резерва — использование расчётной модели; 
 формирование аварийного сигнала; 
 блокировка управления по неисправному каналу. 
4. Построить блок-схему алгоритма. 
5. Описать процедуру замены датчика и восстановления. 
 
Вариант 3. Отказ исполнительного механизма (задвижка не закрывается). 
Требуется: 
1. Описать признаки отказа. 
2. Разработать алгоритм обнаружения: 
 контроль конечных выключателей; 
 контроль времени срабатывания; 
 контроль крутящего момента. 
3. Разработать алгоритм действий: 
 повторная попытка управления; 
 переключение на резервный привод; 
 аварийная остановка насоса; 
 оповещение оператора. 
4. Построить блок-схему. 
5. Описать регламент действий оператора. 
 
Вариант 4. Потеря электропитания основного канала. 
Требуется: 
1. Описать признаки потери питания. 
2. Разработать алгоритм обнаружения. 
3. Разработать алгоритм перехода на резервный источник питания (ИБП, дизель -
генератор). 
4. Разработать алгоритм безопасного завершения технологического процесса при 
длительном отсутствии питания. 
5. Построить блок-схему.

6. Описать порядок восстановления. 
 
 
Методические указания к выполнению 
Шаг 1. Анализ нештатной ситуации. 
 
Опишите: 
 причину возникновения; 
 возможные последствия; 
 признаки, по которым ситуация обнаруживается; 
 доступные ресурсы для парирования. 
Шаг 2. Разработка алгоритма обнаружения. 
 
Используйте: 
 временные задержки (тайм-ауты); 
 счётчики событий; 
 логические условия; 
 сравнение с резервными источниками. 
Шаг 3. Разработка алгоритма парирования. 
 
Структурируйте алгоритм по уровням: 
 уровень контроллера (локальное парирование); 
 уровень SCADA (оперативное управление); 
 уровень диспетчера (организационные решения). 
Шаг 4. Построение блок-схемы. 
 
Используйте стандартные обозначения ГОСТ 19.701-90: 
 овал — начало/конец; 
 прямоугольник — процесс; 
 ромб — условие; 
 параллелограмм — ввод/вывод; 
 цилиндр — база данных. 
Шаг 5. Описание критериев восстановления. 
 
Укажите: 
 условия, при которых система возвращается в нормальный режим; 
 процедуру проверки работоспособности; 
 порядок документирования. 
Шаг 6. Оформление отчёта. 
 
Включите: 
 описание нештатной ситуации; 
 алгоритм в виде блок-схемы; 
 текстовое описание алгоритма; 
 перечень сигналов и сообщений; 
 регламент действий оператора.
