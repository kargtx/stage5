Практическое занятие № 4 
Тема: Проектирование структуры базы данных для системы мониторинга 
параметров 
Цель занятия:  освоить методику проектирования реляционной базы данных для 
хранения и обработки данных мониторинга параметров АС СН; научиться строить ER-
диаграммы и нормализовать структуру. 
 
Продолжительность: 2 часа. 
 
Формируемые компетенции: способность разрабатывать информационное обеспечение 
АС СН. 
 
Теоретическая часть 
Требования к базе данных системы мониторинга: 
1. Высокая производительность записи – данные поступают с периодом от 0,1 до 10 
с. 
2. Долговременное хранение – архивы за несколько лет. 
3. Быстрый доступ – выборка по времени, объекту, параметру. 
4. Целостность – отсутствие потери и искажения данных. 
5. Резервирование – защита от сбоев. 
6. Разграничение доступа – роли пользователей. 
Основные сущности: 
 Объект – технологический объект (насос, задвижка, резервуар). 
 Параметр – измеряемая величина (давление, температура). 
 Измерение – конкретное значение параметра в момент времени. 
 Событие – аварийный сигнал, изменение состояния. 
 Пользователь – оператор, администратор. 
 Устройство – датчик, контроллер. 
Типы данных: 
 для времени – TIMESTAMP; 
 для значений – FLOAT, DOUBLE; 
 для состояний – INTEGER, ENUM; 
 для текста – VARCHAR. 
Нормализация: 
 1НФ – атомарность атрибутов; 
 2НФ – отсутствие частичной зависимости; 
 3НФ – отсутствие транзитивной зависимости. 
 
Задание 
Спроектировать структуру базы данных для системы мониторинга параметров 
нефтеперекачивающей станции. 
 
Этап 1. Анализ предметной области. 
Определить: 
 перечень объектов мониторинга (не менее 5); 
 перечень параметров для каждого объекта (не менее 3); 
 частоту опроса; 
 глубину архива; 

=== PAGE 2 ===
 перечень событий. 
Этап 2. Построение ER-диаграммы. 
Выделить сущности, атрибуты и связи. Пример: 
 Объект (ID_объекта, Название, Тип, Расположение) 
 Параметр (ID_параметра, Название, Единица_измерения, Мин_значение, 
Макс_значение) 
 Устройство (ID_устройства, Тип, Модель, ID_объекта) 
 Измерение (ID_измерения, ID_параметра, ID_устройства, Значение, Время) 
 Событие (ID_события, ID_объекта, Тип, Описание, Время, Уровень) 
 Пользователь (ID_пользователя, Логин, Роль, Пароль) 
Этап 3. Нормализация. 
Привести структуру к 3НФ. Обосновать. 
Этап 4. Разработка DDL-скриптов. 
Написать SQL-запросы для создания таблиц: 
 
CREATE TABLE Объект ( 
    ID_объекта INT PRIMARY KEY, 
    Название VARCHAR(100) NOT NULL, 
    Тип VARCHAR(50), 
    Расположение VARCHAR(200) 
); 
 
CREATE TABLE Параметр ( 
    ID_параметра INT PRIMARY KEY, 
    Название VARCHAR(100) NOT NULL, 
    Единица_измерения VARCHAR(20), 
    Мин_значение FLOAT, 
    Макс_значение FLOAT 
); 
 
CREATE TABLE Измерение ( 
    ID_измерения BIGINT PRIMARY KEY, 
    ID_параметра INT NOT NULL, 
    ID_устройства INT NOT NULL, 
    Значение FLOAT NOT NULL, 
    Время TIMESTAMP NOT NULL, 
    FOREIGN KEY (ID_параметра) REFERENCES Параметр(ID_параметра), 
    FOREIGN KEY (ID_устройства) REFERENCES Устройство(ID_устройства) 
); 
Этап 5. Разработка типовых запросов. 
Составить запросы: 
 выборка последних значений по объекту; 
 выборка среднего значения за смену; 
 выборка аварийных событий за сутки; 
 выборка тренда параметра за час. 
Этап 6. Оптимизация. 
Предложить меры: 
 индексы по времени и ID_параметра; 
 секционирование таблицы измерений по времени; 
 использование временных рядов (TimescaleDB, InfluxDB).

Методические указания к выполнению 
Шаг 1. Определение требований. 
 
Сформулируйте: 
 количество объектов; 
 количество параметров; 
 частоту опроса; 
 глубину архива; 
 количество пользователей. 
Шаг 2. Выделение сущностей. 
 
Используйте метод «существительных»: выпишите все объекты предметной области, 
выделите главные. 
Шаг 3. Определение атрибутов. 
 
Для каждой сущности определите: 
 первичный ключ; 
 обязательные атрибуты; 
 необязательные атрибуты; 
 типы данных. 
Шаг 4. Определение связей. 
 
Укажите: 
 тип связи (1:1, 1:N, M:N); 
 обязательность; 
 правила целостности. 
Шаг 5. Построение ER-диаграммы. 
 
Используйте нотацию «вороньи лапки» (Crow’s Foot) или IDEF1X. 
Инструменты: draw.io, Lucidchart, ERwin, dbdiagram.io. 
Шаг 6. Нормализация. 
 
Проверьте каждую таблицу на соответствие 1НФ, 2НФ, 3НФ. При необходимости 
выполните декомпозицию. 
Шаг 7. Написание SQL. 
 
Создайте DDL-скрипты. Проверьте их выполнение в СУБД (PostgreSQL, MySQL). 
Шаг 8. Тестирование. 
 
Заполните таблицы тестовыми данными. Выполните типовые запросы. Оцените 
производительность. 
 
Пример ER-диаграммы (текстовое описание) 
Объект (1) ----< (N) Устройство 
Объект (1) ----< (N) Событие 
Параметр (1) ----< (N) Измерение 
Устройство (1) ----< (N) Измерение 
Пользователь (1) ----< (N) Событие
